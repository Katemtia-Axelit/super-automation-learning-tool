# 产品路线图 — 基于「逼迫真正思考」的设计哲学

> 编写日期：2026-06-09
> 核心原则：**真正用在思考上的时间越多，学到的就越多**

---

## 一、当前状态评估

### 1.1 已建成的护城河

| 能力 | 现状 | 价值 |
|------|------|------|
| 抽卡系统 | ✅ 完整可用 | 游戏化推送，让用户无法逃避 |
| 任务依赖链 | ✅ 数据层就绪 | 可建立笔记链/习题链 |
| 笔记库 (vault) | ✅ ~200篇笔记 | 知识资产已积累 |
| 知识点库 | ✅ ~150个 | 独立知识节点 |
| 四大Agent提示词 | ✅ 完整 | 内容生产方法论已明确 |

### 1.2 最大的价值缺口

```
当前状态：用户可以抽到复习任务 → 打开笔记 → 看完 → 完成任务
                     ↓
核心问题：看完 ≠ 学会，系统没有验证理解深度
                     ↓
设计哲学的冲突：没有验证，就无法「逼迫真正思考」
```

### 1.3 用户的核心矛盾

你说过：
> 那些本来就不学习的人，我只是削减了他们所有假努力的时间，暴露出他们的真努力原来一直都是零。

**但问题是**：系统现在没有办法区分「真努力」和「看完笔记假装学会了」。

### 第二阶段：建立验证闭环（2-4周）

**目标**：让系统真正能验证「是否真正理解了」

#### P2: 笔记链自动生成

```
价值：建立完整的知识体系依赖关系
现状：103个复习任务已关联笔记，但依赖链未建立

实现内容：
├── 扫描vault文件结构（学科/章节/小节）
├── 按顺序生成笔记链依赖
│   └── 7.1 → 7.2 → 7.3 → ... → 章节复习
├── 生成章节总习题节点
└── 配置跨章衔接

预计工时：8-12小时
```

#### P3-X: 知识侦探模式 ⭐（核心功能）

```
价值：直接验证「是否真正理解了」，而非「是否看过了」
原理：主动召回 + 错误检测的记忆留存率是被动阅读的3-4倍
```

**核心玩法**：

```
正常复习流程：
抽到复习7.1任务 → 打开笔记 → 看完 → 完成

知识侦探模式：
抽到「知识侦探：7.1」任务
    ↓
系统展示「有毒副本」（关键概念被篡改）
    ↓
用户对照原笔记找出错误
    ↓
提交答案，系统判定
    ↓
正确：标记已纠错，+经验
错误：显示正确答案，计入薄弱点
```

**篡改类型**：

| 类型 | 难度 | 示例 |
|------|------|------|
| 数值篡改 | ★ | $\sin x \to \sin 2x$ |
| 符号错误 | ★ | $\vec{a} \cdot \vec{b} \to \vec{a} \times \vec{b}$ |
| 概念替换 | ★★ | 「偏导数」→「全微分」 |
| 概念捏造 | ★★ | 凭空引入不存在的定理 |
| 条件缺失 | ★★★ | 删除「当 $x \to 0$ 时」 |
| 顺序颠倒 | ★★★ | 「由A得B」→「由B得A」 |

**技术实现**：

```
1. 数据库：新建note_corrections表
   - task_id / note_path / tamper_type
   - user_answer / is_correct / created_at

2. 生成API：POST /api/knowledge-detective/generate
   - 内存生成篡改副本（不写vault）
   - 输出：original_segments[] + tampered_segments[]

3. 提交API：POST /api/knowledge-detective/submit
   - 判定 + 记录到note_corrections
   - 薄弱点标记

4. 任务生成：作为knowledge_detective类型接入抽卡

5. 前端UI：
   - 复用复习卡面
   - 增加「对照原笔记」按钮
   - 「提交纠错」表单
```

**与现有系统的关系**：

```
Step 4笔记关联 → knowledge_detective任务复用linked_note_path
P2笔记链 → 纠错任务作为笔记链的辅助验证
弃牌堆 → 可拒绝纠错任务（不影响笔记链解锁）
每日基调 → 精力低时不推送高难度纠错任务
```

**预计工时**：16-24小时

### 第三阶段：内容生产自动化（4-8周）

**目标**：让用户能快速生成新的笔记和知识点

#### P3-1: AI笔记生成流水线UI

```
现状：4个Agent提示词已完备，但无执行入口

流水线：
原始材料（录音/字幕/讲稿）
    ↓
上传接口（Web端）
    ↓
数据清理Agent
    ↓
笔记整理师Agent
    ↓
知识点整理师Agent
    ↓
内容审查师 + 结构审查师
    ↓
预览 + 人工确认
    ↓
写入vault
```

**技术挑战**：
- 需要API Key调用外部AI
- 需要安全的vault写入流程
- 建议：先做只读预览，再逐步开放写入

**预计工时**：20-40小时（视复杂度）

#### P3-2: 知识点质量验证

```
价值：确保vault中笔记和知识点的链接完整性
实现：对比笔记中的[[链接]]和知识点文件的存在性
```

#### P3-3: 知识索引自动维护

```
价值：vault根目录生成索引导航
```

## 三、优先级决策框架

### 决策依据

```
用户的核心设计哲学：「逼迫用户把时间花在真正的思考上」

↓

「真正的思考」如何验证？
├── 被动确认：看完笔记就算完成 ❌
├── 主动验证：做习题 ✓
└── 更强验证：主动纠错 ⭐（知识侦探模式）

↓

优先级排序：
P3-X 知识侦探 > P2 笔记链 > P3 AI生成 > P4 Agent执行
```

### 资源约束下的选择

如果你只有 **2周时间**：
```
只做 P0 + P3-X 知识侦探
→ 系统立刻能验证「是否真正理解了」
```

如果你有 **1个月时间**：
```
P0 + P1 + P2 + P3-X
→ 完整的学习验证闭环
```

## 六、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| P3-X需要AI生成篡改内容 | 中 | 高 | 先用规则生成，AI仅辅助 |
| P2笔记链与现有任务冲突 | 中 | 中 | 先备份，再测试迁移脚本 |
| 过度工程化 | 高 | 中 | 聚焦核心价值，延迟非必要功能 |
| 用户不持续使用 | 高 | 高 | 优先做能立刻产生价值的功能 |

## 七、关键指标

如何判断系统是否在「逼迫真正思考」：

| 指标 | 测量方式 | 目标 |
|------|----------|------|
| 知识侦探完成率 | 完成数/推送数 | >60% |
| 纠错正确率 | 正确数/总纠错数 | 随练习提升 |
| 薄弱点覆盖 | 薄弱概念有对应任务 | >80% |
| 笔记复习vs习题完成比 | 习题完成数/笔记复习数 | 趋近1:1 |

---

> **最终目标**：让用户意识到「看完笔记」不等于「学会了」，让系统成为真正的思考催化剂，而非假努力的庇护所。

# 任务系统重构方案

## 一、设计原则

- **笔记链**：纯笔记顺序，可以独立推进，不被习题阻塞
- **习题链**：每节笔记解锁对应习题，所有小节习题完成后解锁章节总习题
- **两条链互不阻塞**：学完笔记后可自由选择做习题或继续下一章笔记
- **真题链**：章节总习题完成后，根据用户选择的逻辑接入

---

## 二、笔记链（Note Chain）

### 2.1 为什么要链式笔记依赖

> 课本的安排往往有它的道理。如果用户对前面内容陌生，抽到后面的卡也不知道怎么复习。

笔记链的核心是**按课本的自然顺序推进**，因为：

- 后一节的推导往往依赖前一节的结论（如多元函数微分依赖极限与连续的概念）
- 定理的应用条件在后续章节中反复出现（如微分中值定理）
- 复习路径应当保持与学习路径一致，减少认知负荷

**每节笔记只依赖前一节笔记**——这是系统设计的**核心约束**，不是 bug，而是有意为之的心流保护机制。

### 2.2 单章内结构

```
第1节复习 → 第2节复习 → 第3节复习 → ... → 第N节复习 → 章节复习
```

- 每节笔记只依赖前一节笔记（无前置 = 解锁状态）
- 章节复习依赖该章最后一节笔记

### 2.2 跨章大门（关键修正）

```
第1节复习 → 第2节复习 → ... → 章节复习
     │                        │
     └──→ [第1节习题]  ...  └──→ [第N节习题]
                                       │
                              所有小节习题 → [章节总习题]
                                             │
                              章节总习题 ─────┼────→ [第(N+1)章第1节复习] ← 解锁大门
```

> **修正（2026-06-09）**：跨章节的第一节笔记，解锁条件从「章节复习」改为「**章节总习题完成**」。

**理由**：如果仅依赖章节复习就能跳到下一章，用户完全可以把 7.1~7.6 的所有笔记草草过一遍（只要快速浏览就算"复习"了），不做任何习题就继续跳到 8.1。系统的设计**不允许绕过习题**，章节总习题是必须跨过的门槛。

- 章节复习 = 知识回顾（快速浏览笔记 → 梳理脉络）
- 章节总习题 = 理解验证（必须实际运用知识解题）
- **系统用总习题这道门槛，确保用户真正掌握该章内容后才能进入下一章**

### 2.3 数据来源

笔记顺序可以从知识库目录自动读取，要求每个科目：
- 文件夹结构按章节命名（如 `06_01_向量的数量积`）
- 或在配置文件中声明章节目录结构

## 三、习题链（Exercise Chain）

### 3.1 单章内结构

```
第1节复习 → 习题1
第2节复习 → 习题2
第3节复习 → 习题3
...
第N节复习 → 习题N

习题1, 习题2, ..., 习题N → 章节总习题（章节习题）
```

- 每节习题依赖该节复习笔记
- 章节总习题依赖该章所有小节习题全部完成

### 3.2 跨章独立

- 各章习题链互不依赖
- 做完第一章所有习题 ≠ 必须做第二章习题（第二章习题解锁依赖第二章笔记完成）

---

## 四、两条链的完整依赖图

以某一章为例（假设该章有3节）：

```
[第1节复习]  (无前置，解锁)
    │
    ├──→ [第1节习题]  (依赖第1节复习)
    │
    └──→ [第2节复习]  (依赖第1节复习)
              │
              ├──→ [第2节习题]  (依赖第2节复习)
              │
              └──→ [第3节复习]  (依赖第2节复习)
                        │
                        ├──→ [第3节习题]  (依赖第3节复习)
                        │
                        └──→ [章节复习]  (依赖第3节复习)
                                  │
                         章节复习 ──┼──→ 继续复习同章任意节（自由浏览）
                                  │
               所有小节习题 ───────┼────→ [章节总习题]  ← 跨章大门
                                           │
                              章节总习题 ──┴────→ [第(N+1)章第1节复习]  (强制门槛)
```

### 关键特性

- **章内笔记链式推进**：每节笔记依赖前一节笔记，确保按课本顺序学习
- **笔记链和习题链独立推进**：学完第1节笔记后，可继续学第2节笔记而不必先做第1节习题
- **章节总习题是跨章大门**：必须通过总习题验证，才能进入下一章——这是防止假努力的硬约束

## 五、真题链（Exam Chain）

章节总习题完成后，根据用户选择的逻辑接入真题。

### 5.1 逻辑一：按卷子（题号顺序）

```
第一章总习题, 第二章总习题, ... → 真题卷1-选择题
第一章总习题, 第二章总习题, ... → 真题卷1-填空题
第一章总习题, 第二章总习题, ... → 真题卷1-计算题

真题卷1-选择题, 真题卷1-填空题, 真题卷1-计算题 → 真题卷1-批改并复盘

真题卷1-批改并复盘 → 真题卷2-选择题
真题卷1-批改并复盘 → 真题卷2-填空题
真题卷1-批改并复盘 → 真题卷2-计算题

真题卷2-选择题, 真题卷2-填空题, 真题卷2-计算题 → 真题卷2-批改并复盘
...
```

- 每套卷子的三个题型并行解锁（均依赖章节总习题完成）
- 批改复盘后解锁下一套卷子

### 5.2 逻辑二：按知识板块（横向）

```
第一章总习题 → 真题卷1-第1题(第1章板块)
第一章总习题 → 真题卷2-第1题(第1章板块)
第一章总习题 → 真题卷3-第1题(第1章板块)

第二章总习题 → 真题卷1-第2题(第2章板块)
第二章总习题 → 真题卷2-第2题(第2章板块)
第二章总习题 → 真题卷3-第2题(第2章板块)

...（以此类推，每章完成后并行做所有卷子的对应题）

真题卷1-第1题, 真题卷1-第2题, ... → 真题卷1-批改并复盘
真题卷2-第1题, 真题卷2-第2题, ... → 真题卷2-批改并复盘
...
```

- 按知识板块分组，每学完一章同步做所有卷子中对应章节的题目
- 可以横向对比同一知识点的不同考法

### 5.3 逻辑三：按题型（纵向）

```
第一章总习题, 第二章总习题, ... → 真题卷1-选择题
第一章总习题, 第二章总习题, ... → 真题卷2-选择题
第一章总习题, 第二章总习题, ... → 真题卷3-选择题

真题卷1-选择题, 真题卷2-选择题, 真题卷3-选择题 → 题型训练-选择题专题

第一章总习题, 第二章总习题, ... → 真题卷1-计算题
第一章总习题, 第二章总习题, ... → 真题卷2-计算题
第一章总习题, 第二章总习题, ... → 真题卷3-计算题

真题卷1-计算题, 真题卷2-计算题, 真题卷3-计算题 → 题型训练-计算题专题
```

- 按题型横向汇总，集中攻克同类题型

## 六、用户配置（创建任务时的输入）

### 6.1 必填项

| 字段 | 说明 |
|------|------|
| 学科名称 | 如 "高等数学" |
| 章数 | 如 11 |
| 每章节数 | 数组，如 [6, 6, 2, 2, 6, 7, 2, 2, 5, 7] |
| 卷子数量 | 如 3（指真题套数）|
| 真题逻辑 | 1 / 2 / 3 |

### 6.2 可选：自动读取知识库

如果知识库目录结构规范（如 `高数/06_01_向量的数量积.md`），系统可以自动：
- 读取章节数
- 读取每章小节数
- 按文件名排序确定笔记顺序
- 自动生成任务名称

### 6.3 手动追加

- 任意额外任务可手动添加
- 手动任务可指定依赖关系
- 手动任务可独立于自动生成的任务链

## 七、任务类型枚举

| 类型 | 前置依赖 | 说明 |
|------|---------|------|
| `note` | 前一节笔记（或无） | 笔记复习 |
| `exercise` | 同节笔记 | 课后习题 |
| `chapter_review` | 最后一节笔记 | 章节复习（知识脉络梳理，可自由浏览） |
| `chapter_exam` | 所有小节习题 | **章节总习题（跨章大门，必须完成才能进入下一章）** |
| `exam_question` | 章节总习题（所有章）| 真题题目（逻辑1/2/3）|
| `exam_review` | 同卷所有题目 | 批改并复盘 |
| `topic_review` | 同题型所有题 | 题型专题（逻辑3）|
| `other` | 自定义 | 用户手动添加 |

> **注**：`大物-题库-选择题/填空题/判断题/计算题` 属于 `exam_question` 类型，接入逻辑为**逻辑2（按知识板块）**。其前置为各章 `chapter_exam`。

## 八、实现步骤（Step by Step）

### Step 1：重建笔记链 + 习题链 + 跨章大门

遍历数据库，按 `学科-章节-小节` 结构重新生成依赖：

```
笔记链:   第1节复习 → 第2节复习 → ... → 章节复习
习题链:   第1节复习 → 第1节习题
          第2节复习 → 第2节习题
          ...
章节汇总: 习题1, 习题2, ..., 习题N → 章节总习题
跨章大门: 章节总习题(第N章) ──→ 第(N+1)章第1节复习   ← 【关键修正】
```

> **注意**：跨章衔接的前置从「章节复习」改为「章节总习题」。

**自动识别方式**：
- 从知识库目录读取 `学科/章节序号_小节序号_文件名.md` 格式
- 或用户手动填写：`{ "高数": [6, 6, 2, 2, 6, 7, ...], "大物": {...} }`

**数据迁移**：
- 保留已完成任务的 `completed=1` 状态
- 清理 `prerequisite_ids` 中指向旧有习题前置的依赖
- 保留已完成任务的历史记录

### Step 2：添加章节总习题节点

每章新增/修改一个 `章节总习题` 任务：
- `task_type = 'chapter_exam'`
- `prerequisite_ids = [习题1_id, 习题2_id, ..., 习题N_id]`

### Step 3：接入真题链（用户配置）

根据用户选择的逻辑，生成真题任务节点：

**逻辑1（按卷子）**：
```
chapter_exam(所有章) → exam_question(卷N-题型X)
exam_question(卷N-题型A/B/C) → exam_review(卷N)
exam_review(卷N) → exam_question(卷N+1-题型A/B/C)
```

**逻辑2（按知识板块）**：
```
chapter_exam(第N章) → exam_question(卷1-第N章板块)
chapter_exam(第N章) → exam_question(卷2-第N章板块)
exam_question(卷M-所有板块) → exam_review(卷M)
```

**逻辑3（按题型）**：
```
chapter_exam(所有章) → exam_question(所有卷-题型X)
exam_question(所有卷-题型X) → topic_review(题型X专题)
topic_review(所有题型) → 考前综合复盘
```

### Step 4：手动追加任务（独立功能）

用户可随时手动添加任务：
- 指定任务名称、任务类型（`other`）
- 可选指定依赖关系（支持多前置）
- 独立于自动生成的任务链

## Step 4：笔记 → 复习任务 深度绑定（本次实现）

### 目标

系统根据知识库中的**笔记文件**自动生成对应的复习任务，抽卡卡面直接关联该笔记的 Obsidian 链接。

### 核心概念

- **每篇笔记对应一个复习任务**（一对一映射，不多不少）
- 复习任务的 `name` = 笔记文件名
- 复习任务的 `linked_note_path` = 笔记的 vault 相对路径（如 `大学物理/01_质点运动描述的物理量.md`）
- 抽卡卡面上显示「在 Obsidian 中打开」按钮，点击后跳转 Obsidian

### 数据库变更

`tasks` 表新增字段：

```sql
ALTER TABLE tasks ADD COLUMN linked_note_path TEXT;
```

### 任务生成逻辑

遍历 `vault/` 下所有学科目录，对每个 `.md` 文件：

```
笔记文件: 大学物理/01_质点运动描述的物理量.md
    → 生成任务:
      name = "01_质点运动描述的物理量"
      linked_note_path = "大学物理/01_质点运动描述的物理量.md"
      task_type = "note_review"
      prerequisite_ids = []  （无前置，自动解锁）
```

> **注意**：本步骤**仅生成复习任务**，不生成习题、章节复习、真题链。后续步骤按需追加。

### 前端卡面变更

抽到的复习任务卡面上新增一个「在 Obsidian 中打开」按钮（图标：`fa-brands fa-markdown`），样式与「开始任务」「跳过」等按钮并列。

点击后调用 `POST /api/knowledge/open-in-obsidian` 打开笔记。

### API 变更

| 接口 | 变更 |
|------|------|
| `POST /api/tasks` | 新增 `linked_note_path` 字段写入 |
| `PUT /api/tasks/<id>` | 新增 `linked_note_path` 字段更新 |
| `GET /api/tasks` | 返回数据中包含 `linked_note_path` |
| `GET /api/gacha/draw` | 返回的 task 包含 `linked_note_path` |

### 实现步骤

1. ✅ `tasks` 表新增 `linked_note_path TEXT` 列
2. ✅ `api_create_task` / `api_update_task` 支持读写 `linked_note_path`
3. ✅ 任务自动生成时，从笔记文件名建立关联
4. ✅ 前端抽卡卡面渲染 Obsidian 链接按钮
5. ✅ 重建任务数据并验证

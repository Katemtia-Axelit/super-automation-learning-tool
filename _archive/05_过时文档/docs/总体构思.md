# 超级自动化学习工具 — 总体构思

> 📌 编写日期：2026-06-09
> 📌 本文档整合项目的核心理念、架构设计与设计哲学，作为项目的顶层说明文档。

---

## 一、项目定位与核心问题

### 1.1 这个项目解决什么问题

学习的本质是**思考**，而非记录。但学生往往把"整理笔记"本身当成学习，陷入**假努力**——机械地抄写、复制，却从未真正理解。

> 真正用在思考上的时间越多，学到的就越多。

本工具的设计目标：**把假努力的时间削减到零，逼迫用户把时间花在真正的思考上。**

### 1.2 核心矛盾

|| 传统方式 | 本系统的方式 |
|------|---------|-------------|
| 笔记制作 | 手抄/打字，2小时 | 一键生成，2分钟 |
| 复习材料 | 临时整理，碎片化 | 体系化知识网络 |
| 练习 | 可做可不做 | 抽卡强制推送 |
| 理解检测 | 期末见分晓 | 逐节习题验证 |

### 1.3 目标用户

- **核心用户**：想自律但经常被外界打断、或因内驱力不足而拖延的大学生和社会人士
- **非目标用户**：完全不爱学习的小学生初中生（首要目标是培养学习习惯，不是本工具的职责）
- **核心洞察**：用户可以骗系统，但系统的目标从来不是与用户对抗，而是**让用户和自己协作，不再骗自己**

## 二、设计哲学

### 2.1 关于"抄笔记"的反思

> 有人问：如果我手抄笔记，至少我有些时候会理解，但是一键生成笔记我连抄的过程都没有，谈何理解？

这是把**假努力当成真努力必要的代价**。

> 如果一直是真正在思考的话，这些繁琐的工作本来可以避免。

本系统的立场：
- **手抄笔记 ≠ 理解**。按录音键后什么都不管然后以为记了笔记就学会，思考时间是零
- **整理笔记 ≠ 学习**。整理笔记本身可能成为一种危险的假努力行为
- **真正有价值的是**：理解材料 → 提取知识 → 建立关联 → 运用练习

### 2.2 关于"看视频/看讲义会走神"的反驳

> 会有人说：看讲义可能看困，可能看不进脑子，可能走马观花。

这是客观存在的现象。但解决方案不是让学生去抄写，而是：
- **建立即时反馈机制**：抽卡系统让你知道自己"不知道什么"
- **降低启动阻力**：2分钟生成笔记，让整理笔记不再痛苦
- **强制输出验证**：习题是理解深度的试金石

### 2.3 关于"学以致用"的学习目的论

> 我们学习的最终目的是为了用——学以致用。

不管这个"用"是：
- 纯粹应对考试（刷真题、刷习题库）
- 还是实际的生产生活场景

系统的另一面——**任务抽卡系统**包含大量习题任务，正是逼迫你去"用"的表现。

### 2.4 心流体验设计

单张内，某节的习题**只依赖**这一节：

> 做不做这一节的习题，**并不会影响**下一节笔记复习的开放。

也就是说：
- 抽到复习7.1的卡后，可以趁着状态继续去复习7.2
- 不必被系统中途拽出来，强制做7.1的习题

这是一种**好的心流体验**，是系统鼓励的。

### 2.5 系统边界

> 那些本来就不学习的人，我只是削减了他们所有假努力的时间，暴露出他们的真努力原来一直都是零。

系统的设计**不与用户对抗**，但会：
- 暴露假努力的本质
- 提供真正的思考工具
- 用习题验证理解深度

### 3.2 数据流与分层职责

| 层级 | 功能 | 核心产物 | 是否存档 |
|------|------|----------|----------|
| **原料层** | 录音/字幕/讲稿 | 原始文本 | ✅ 永久存档 |
| **清洗层** | 数据清理Agent | 规范化文本 | ✅ 存档 |
| **笔记层** | 笔记整理师Agent | 结构化Markdown笔记 | ✅ 永久存档 |
| **知识层** | 知识点整理师Agent | 独立知识点文件 | ✅ 永久存档 |
| **审查层** | 内容审查师 + 结构审查师 | 质检报告 + 修正 | ✅ 存档 |
| **任务层** | 任务发布系统 | 复习任务卡片 | — |
| **验证层** | 习题抽卡 | 理解验证 | — |

**层层都有文本存档**——这是精确性的保障：
- 原始文本可追溯
- 笔记与原始文本之间的映射关系明确
- 知识点的来源可直接回溯

### 3.3 两类Agent的分工

#### 内容审查师 vs 结构审查师

| 维度 | 内容审查师 | 结构审查师 |
|------|-----------|-----------|
| ✅ 事实准确性 | **负责** | 不负责 |
| ✅ 逻辑一致性 | **负责** | 不负责 |
| ✅ 知识完整性 | **负责** | 不负责 |
| ✅ 公式正确性 | **负责** | 不负责 |
| ✅ 内容可读性 | **负责** | 不负责 |
| ❌ 格式规范性 | 不负责 | **负责** |
| ❌ 结构完整性 | 不负责 | **负责** |
| ❌ 链接健康度 | 不负责 | **负责** |

#### 知识点与笔记的天然隔阂

> 实际上由于知识点是直接从笔记中提取的，和原始文本之间已经有了天然的隔阂。

这意味着：
- 笔记可能有理解偏差
- 但知识点是二次加工，需要单独验证
- **内容审查师需要同时检查笔记内容对不对、知识点对不对**
- 检查笔记的事实性正确性和知识点的事实性正确性

## 四、四大Agent详解

### 4.1 笔记整理师

**输入**：原始录音/字幕清洗后的文本  
**输出**：结构化Markdown笔记

**核心原则**：
1. **逻辑树优先于时间线**：知识的本质是概念之间的依赖关系，不是老师说话的先后顺序
2. **链接即理解**：每篇笔记必须成为知识网络中的一个可导航节点
3. **考试导向的密度控制**：高频考点展开推导，低频概念精炼定义

**工作流程**：
```
深度清洗与术语校准 → 内容提取与分层 → 知识增强与链接构建 → Obsidian格式化
```

### 4.2 知识点整理师

**输入**：笔记整理师产出的笔记  
**输出**：独立知识点Markdown文件

**核心原则**：
- 每一行文字都必须有实际教学价值
- 知识点之间必须有前置依赖和后续应用的链接
- 禁止占位符和待补充内容

**知识点模板**：
```markdown
# [知识点名称]
> 🏷️ 标签：#主题分类 #难度等级 #方法类型

## 一句话定义
[≤30字精准概括]

## 核心内容
[公式 + 变量说明]

## 通俗理解
[生活类比/直观解释]

## 使用前提
## 知识网络（前置 → 当前 → 后续）
## 典型例题
## 常见错误
```

### 4.3 内容审查师

**输入**：笔记 + 知识点 + 原始参考  
**输出**：质检报告

**核心职责**：
- 学术验证与事实核查
- 知识一致性与内容可读性保障
- 知识点是否完整覆盖笔记中的核心概念

**审查维度**：
- 概念定义是否准确
- 公式定理是否正确
- 例题分析是否完整
- 知识网络是否连贯
- 内容密度是否符合考试导向

### 4.4 结构审查师

**输入**：笔记Markdown文件  
**输出**：结构审查报告

**核心职责**：
- 格式规范性检查（Markdown语法、Callout、Mermaid）
- 结构完整性检查（思维导图、知识网络章节）
- 链接健康度检查（无死链、无自引用）

## 五、任务系统设计

### 5.1 核心设计原则

- **笔记链优先**：笔记复习任务是核心，习题是辅助验证
- **笔记链和习题链互不阻塞**：学完第1节笔记后可继续学第2节，不必先做第1节习题
- **习题是理解深度的验证**：做不做习题不影响下一节笔记的开放，但系统不允许跳过所有习题

### 5.2 任务类型

| 类型 | 说明 |
|------|------|
| `note_review` | 笔记复习任务（与Obsidian笔记一一对应） |
| `exercise` | 课后习题 |
| `chapter_review` | 章节复习 |
| `chapter_exam` | 章节总习题 |
| `exam_question` | 真题题目 |

### 5.3 依赖规则

- 每节笔记只依赖前一节笔记（形成笔记链）
- 每节习题依赖该节复习笔记
- 章节总习题依赖该章所有小节习题全部完成
- **跨章衔接仅依赖章节复习**：不影响用户在章节间自由选择

### 5.4 抽卡机制

- **3个卡池**：碎片（0-15min）、番茄（15-45min）、深度（45min+）
- **加权随机**：基于优先级、DDL紧迫度、精力匹配、阻力系数
- **换牌机制**：不满意的卡可以选择换牌
- **弃牌堆**：拒绝的任务进入弃牌堆，可随时恢复

## 六、知识库结构

### 6.1 五级知识网络

```
知识索引（根节点）
    └── 科目（二级节点：大物、高数、线代、计算机、电子技术、英语四级）
        └── 模块（三级节点：如大物-力学、大物-热学、高数-微积分）
            └── 笔记（四级节点：具体笔记文件）
                └── 知识点（五级节点：正文中出现的核心概念）
```

### 6.2 链接规则

- **笔记只链接知识点文件，不链接其他笔记**
- 笔记中首次出现的核心知识点必须添加双向链接 `[[知识点名]]`
- 知识点之间建立前置依赖和后续应用的链接关系

### 6.3 笔记模板结构

```markdown
# [学科]：[主题]

> 📌 重构说明：...

## 🧠 思维导图
[mermaid mindmap]

## 一、[核心概念1]
### 1.1 定义与直观理解
### 1.2 推导/运算逻辑
### 1.3 易错辨析
### 1.4 典型例题

## 🔗 知识网络
### 前置依赖
### 后续延伸
### 对比辨析

## 📚 核心词条索引
```

## 七、与其他学习方式的对比

### 7.1 vs 传统手抄笔记

| 维度 | 传统手抄 | 本系统 |
|------|---------|--------|
| 时间成本 | 2-3小时/节 | 2-5分钟 |
| 可搜索性 | 纸质或散乱文件 | Obsidian全文搜索 |
| 知识关联 | 依赖人工发现 | 自动建立链接网络 |
| 复习效率 | 重新阅读全部内容 | 知识点卡片+习题验证 |
| 理解检测 | 期末考试见分晓 | 逐节习题即时验证 |

### 7.2 vs 普通笔记软件

| 维度 | 普通笔记软件 | 本系统 |
|------|------------|--------|
| 笔记来源 | 手动整理 | AI自动生成 |
| 知识点 | 散落在笔记中 | 独立抽取、标准化 |
| 复习推送 | 无 | 抽卡游戏化推送 |
| 理解验证 | 无 | 逐节习题机制 |

### 7.3 vs 题库刷题软件

| 维度 | 题库刷题 | 本系统 |
|------|---------|--------|
| 材料来源 | 分散在各个渠道 | 笔记→习题一体化 |
| 复习节奏 | 随机或按章节 | 抽卡+艾宾浩斯 |
| 理解深度 | 刷过即忘 | 笔记复习→习题验证闭环 |

## 十、设计红线

> 系统的设计目标从来不是与用户对抗，而是让用户和自己协作。

- ❌ 不引入复杂前端框架（Vue/React/Vite）
- ❌ 不恢复旧的内联JS
- ❌ 不删除核心数据库
- ❌ 不让Agent直接写vault（当前为只读模式）
- ❌ 不让Agent直接import tasks（需人工确认）
- ❌ 不自动改抽卡权重
- ❌ 不跳过人工确认做自动化写入

### 🟠 P3-X — 知识侦探模式（笔记纠错挑战）

> 来自用户创意，充分利用笔记-任务深度绑定的独特优势。

**核心玩法**：系统对笔记中的关键概念进行**受控篡改**（替换、删除、捏造），生成一份"有毒副本"，要求用户在复习时找出并纠正。

#### 设计理念

| 维度 | 说明 |
|------|------|
| 学习原理 | **主动召回 + 错误检测**比被动阅读的记忆留存率高 3-4 倍 |
| 主动纠错 | 找到错误比记住正确答案更令人印象深刻 |
| 考试导向 | 考前自测时识别陷阱题的能力直接决定得分 |
| 笔记质量 | 同时提升笔记质量（纠错会反哺 vault）|

#### 篡改类型

| 类型 | 原理 | 难度 |
|------|------|------|
| **概念替换** | 将关键词汇替换为相邻概念（如"偏导数"→"全微分"） | ★★ |
| **数值篡改** | 修改公式系数或参数（如 $\sin x \to \sin 2x$） | ★ |
| **条件缺失** | 删除关键前提条件（如"当 $x \to 0$ 时"） | ★★★ |
| **概念捏造** | 凭空引入不存在的定理或结论 | ★★ |
| **顺序颠倒** | 颠倒因果关系（如"由A得B"→"由B得A"） | ★★★ |
| **符号错误** | 改变运算符号（如 $\vec{a} \cdot \vec{b}$ → $\vec{a} \times \vec{b}$） | ★ |

#### 任务类型：`knowledge_detective`

| 字段 | 值 |
|------|------|
| `task_type` | `knowledge_detective` |
| `linked_note_path` | 对应笔记路径（复用 Step 4 关联） |
| `description` | 纠错副本摘要（篡改数量、类型）|
| `difficulty` | 按篡改类型难度加权 |
| `tags` | 含 `["纠错", "主动学习"]` |

#### 生成流程

```
触发条件：用户完成某节笔记复习任务后解锁
    │
    ▼
AI 生成层（受控篡改）
    │
    ├── 读取原始笔记 [[linked_note_path]]
    ├── 按规则选择篡改点（N 个，难度加权）
    ├── 生成篡改副本（仅内存，不写 vault）
    └── 输出：original_segments[] + tampered_segments[]
    │
    ▼
任务卡片
    │
    ├── 显示篡改副本（不暴露篡改位置）
    ├── 用户对照原笔记找出错误
    └── 提交答案：指出错误位置 + 正确内容
    │
    ▼
判定层
    │
    ├── 系统对比用户答案与篡改记录
    ├── 正确：标记为已纠错，+完成经验
    └── 错误或遗漏：提示正确答案，计入复习薄弱点
```

#### 难度分级

| 等级 | 篡改数量 | 篡改类型 | 适用场景 |
|------|----------|----------|----------|
| 入门 | 1 处 | 数值篡改、符号错误 | 新学某节后 |
| 基础 | 2 处 | +概念替换、概念捏造 | 复习阶段 |
| 进阶 | 3 处 | +条件缺失、顺序颠倒 | 考前模拟 |
| 大师 | 4-5 处 | 混合类型 | 挑战模式 |

#### 纠错结果闭环

- **纠错记录**：每次纠错记录写入 `note_corrections` 表（新建）
  - `task_id` / `note_path` / `tamper_type` / `user_answer` / `is_correct` / `created_at`
- **薄弱点标记**：纠错失败的概念加入「薄弱知识点库」，后续复习任务优先推送
- **笔记质量反馈**：纠错数据汇总后，可生成《笔记问题报告》，指导知识点整理师修复 vault

#### 与现有系统的关系

| 模块 | 关系 |
|------|------|
| Step 4 笔记关联 | `knowledge_detective` 任务复用 `linked_note_path` |
| P2 笔记链 | 纠错任务可作为笔记链的辅助验证（替代部分习题）|
| 弃牌堆 | 用户可拒绝纠错任务（不影响笔记链解锁）|
| 每日基调 | 精力低时不推送高难度纠错任务 |

#### 技术实现路径

1. **数据库**：新建 `note_corrections` 表 + `tamper_templates` 表（篡改规则模板）
2. **生成 API**：`POST /api/knowledge-detective/generate`（内存生成，不写 vault）
3. **提交 API**：`POST /api/knowledge-detective/submit`（判定 + 记录）
4. **任务生成**：作为 `knowledge_detective` 类型任务接入抽卡系统
5. **前端 UI**：复用现有复习卡面，增加「对照原笔记」按钮（打开 Obsidian）和「提交纠错」表单

#### 风险控制

- ❌ 不写 vault：篡改副本仅在内存/临时表中，不修改原始笔记
- ❌ 不自动修复笔记：纠错结果仅供用户手动确认后修改 vault
- ❌ 不暴露篡改位置：前端仅显示篡改副本，不在 UI 中标注差异

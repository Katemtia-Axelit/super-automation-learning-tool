## 1. 产品的真实宗旨（用户已经明确）

这是以**智能任务决策与派发**为核心的个人行动系统。目标是减少决策成本，让用户在有限的时间和精力下，做最值得做、又适合当前状态的行动，追求可检验的**真实成果**，而非表面的任务数量/用时。行动包括学习、锻炼、整理、恢复、生活及工作等。

任务抽卡是核心派发入口，**动态权重**是决策机制。用户明天考试时复习可压倒性占优；连续学习精力下滑时，运动十分钟、整理桌面或远眺可暂时变为更优任务。候选项接近时使用加权抽卡；某个候选项形成压倒性优势时按类似“多数偏好”的理念**直接推荐，不强行随机**。权重随状态恢复而重新调整。用户与系统合作，保有行动选择权。

笔记库、知识图谱、状态日志、AI 知识加工、习题与学习结果记录，根本上是为生成高质量候选任务、判断真实收益、改善动态派发提供信息；不是为了堆积功能。长期使用界面应当舒适、统一、可以像“半个壁纸”一样常驻。复古幻想只是当前偏好的视觉方向，未来可能替换蒸汽、科幻等完整主题皮肤，因此视觉资源应尽可能与任务逻辑解耦。

## 2. 特别纠正：当前八个“学科主题”不是产品最终卡牌分类

当前 `static/app.js` 的 `resolveTaskCardTheme(task)` 按名称/标签/描述关键词选择 `theme-math/lang/history/code/write/science/review/default`；`static/assets/art-manifest.json` 和 `src/index.html` 有对应 CSS/路径接口。这是既存技术实现，而非产品原则，更不是已获用户批准的最终美术分类。

**停止把这八项等同于八个实际学科、固定课表或必须画出的八张不同科目封面。** 过去“第一批先画八科”的创作任务需在双方讨论后重定；如果绘图对话已画出类似作品，不要废弃，可以考虑重用为题材变体、插画部件、稀有度装饰或现有兼容主题。

用户提出的更合理方向是**按任务的认知与行动性质分类**，例如数理逻辑、算法/结构、人文阅读思考、身体锻炼、放松恢复等。这些只是讨论起点，不是新冻结分类表；建议继续讨论组织整理、表达创作、事务生活等行为该如何呈现。

特别区分三条相互独立的轴：

1. **任务真实用途/行为类型**：需要抽象推理、算法分析、阅读思辨、体力活动、环境整理、恢复休息等。用于选择任务卡面语义，当前尚未确定粒度和归属。
2. **任务背景/领域标签**：概率论、语言、历史、编程等只是可选标签或二级点缀，不必决定独立的主卡面。
3. **任务状态与派发条件**：紧急、优先级、是否解锁、当前能量需求、是否直接优势推荐、任务完成或弃牌等。应优先使用统一的徽记/文字/框架状态，不必各画一整张背景。尤其“复习”是一种活动形式，而非与数学、人文平级的学科。

另外代码中的五个普通任务类别 `study/exercise/work/life/other` 是现有数据库/界面分类，也不能自动等同于未来美术主题数或视觉分类。

## 3. 美术和程序当前可核验的事实

- 前端已实现任务卡牌、抽卡/多抽、翻牌/飞行、计时 Dock、弃牌堆、状态和反馈弹窗；任务选择/类别相关代码仍使用旧八主题关键词推断。
- 现行 SVG 路径 `static/assets/cards/faces/theme-{math,lang,history,code,write,science,review,default}/front-bg.svg` 等只是旧注册器绑定；**不得从这里推导新视觉分类名称**。修改名称需要正式迁移与兼容方案，不能让美术或 Worker 擅自直接批量重命名。
- 2026-10-12 检测：合成 60/60、真实 TEMP Factory E2E 7/7、默认八主题无素材视觉回退通过，但生产 `static/assets` 下无实际 SVG 成品。
- SVG 注册器目前存在已独立复现的安全缺陷（onload、CSS @import、含 script 的 fail-closed）。**正式资源导入前必须修复与复测，不得将未审查 SVG 交给生产 build。**
- 本机项目目录内尚未定位到绘图对话产出的图片/可编辑源文件。它们可能位于对话附件或未共享的路径；不能推断为不存在，也不能评价其完成度。

## 4. 双方必须共同确认的设计约定（暂不冻结）

1. **视觉分类层级**：到底需要几个“行为原型”主卡面？哪些可共用背景，仅用图标/徽记差异化？是否允许一张任务映射多种原型？用户须最终审核。
2. **卡牌作用与状态**：卡背/正面/飞行/弃牌如何表达任务选择、接受、直接优势推荐、完成、恢复等？哪些视觉含义足够直观、不依赖理解复杂符号？
3. **信息布局**：标题、预计时长、类型、优先级、按钮、状态提示的安全留白；横屏与窄屏需同时考虑，不能把动态数字固定画进 SVG。
4. **视觉世界观与复用**：统一的复古幻想设计语言、背景/边框/角饰/徽记/题材纹样分层；未来完整换肤需要哪些可独立替换资源？
5. **已产出美术作品清点**：请绘图端提供文件名/预览/源稿/设计意图、长宽比例、文字安全区、预计对应的行为原型及可复用部件。先盘点，不要要求画师把现有作品推倒重来。
6. **程序接口改造策略**：在美术原型确定后，由工程 Controller 设计“稳定语义 ID→资源路径→兼容别名/回退”的版本化映射；减少 UI 源码的关键词硬编码，同时**不改变核心任务权重算法**。对尚未接线变量/状态明确标注，单独测试。
7. **恢复与健康任务**：它们是有真实价值的任务类别，而非复习失败的惩罚、附属彩蛋。美术需使其保持尊重用户的舒适感，避免暗示“不够勤奋”。
8. **功能优先**：视觉设计用于降低阻力、增加意愿、提供舒适界面，不能牺牲可读性、操作效率、无障碍、性能或用户真实目标。

## 5. 面向绘图对话的本轮磋商请求

请勿直接按旧八科继续扩产。请先提供已有美术成果的清单/预览（可共享文件或路径），说明已成形的统一设计语言及可以复用的元素。随后提出**2～3 个候选的视觉分类体系**，重点解释：为何这种分类更符合任务的行为性质、不同原型如何共享同一世界观、能否用少量部件组合承载更多任务类型，以及现有作品如何保留利用。

程序端承诺：本轮只审查既有接口和协商数据映射，不未经沟通强推八科，也不要求美术对话改代码。用户对最终视觉分类、艺术方向、是否保留现有卡面的决定具有最高优先权。

## 6. 需要程序端处理但目前**没有获准改变代码**的事项

- 在最终分类决定后，审计并改造 `resolveTaskCardTheme` 与 manifest 的映射，将“课程关键词”降为可选辅助而非唯一决定者；保留旧资源兼容回退。
- 修复 SVG 安全校验（下一项任务 S 尚未在 Batch 登记或正式派发），完成合法与危险素材的独立注入测试。
- 建立美术接口/素材语义清单，标记每个槽位已实现、仅存在清单、尚未消费、待设计；与画师作品逐一配对，避免重画和 404。
- 可考虑未来完整换肤；当前不必承诺已经具有主题市场、多设备同步等能力。

**结论：现在先完成语义与视觉的对齐，再冻结第一版卡面接口并推进素材接线。美术已有成果应优先盘点复用，不因为程序早期八主题关键词就推翻。**

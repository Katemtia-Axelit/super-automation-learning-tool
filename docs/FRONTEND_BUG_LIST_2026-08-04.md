## 二、高风险区标注

| 区域 | 风险等级 | 理由 |
|------|---------|------|
| **计时器系统** | 🔴 极高 | 双状态机（timerDockSession vs timerActiveSession）、本地模拟暂停、interval 未清理；任何改动可能引发"计时加倍"、"状态不同步"等严重问题 |
| **抽卡流程** | 🔴 高 | `drawGacha` → `renderDrawnCard` → 动画 → 任务操作 → 反馈 的长链路；动画与状态更新之间的竞态是 bug 高发区 |
| **任务依赖解锁** | 🔴 高 | `prerequisite_ids` 与 `task_dependencies` 双写，后端解锁链逻辑复杂；前端只显示提示，不校验依赖是否真的已满足 |
| **弃牌堆操作** | 🟡 中 | `completeWithFeedback()` 先完成再移入弃牌堆（L847），但顺序与其他路径（`moveToDiscard`）不一致；可能导致已完成任务被重复处理 |
| **日程/睡眠** | 🟡 中 | 依赖多个 API 端点；部分表（`daily_schedules`、`activities`）可能为空，错误处理不完善 |
| **知识库浏览** | 🟢 低 | 只读操作，风险相对较低；但 Markdown 解析简陋影响阅读体验 |

## 四、验证方式建议

### P0-1 计时器 interval 未清理
**验证步骤**：
1. 打开浏览器 DevTools Console
2. 访问抽卡页面，观察 `timerDockTick` interval ID
3. 手动在 Console 执行 `showPage('tasks')` 切换到任务页
4. 再次执行 `showPage('gacha')` 切回抽卡页
5. 多次切换，观察计时 Dock 数字是否加倍（正常：每秒+1；异常：每秒+2 或更多）

**修复验证**：切换后 Console 应只有 1 个 interval 在运行（用 `getEventListeners(window)` 或记录 interval 数量验证）

### P0-2 提前结束任务状态不一致
**验证步骤**：
1. 新建一个测试任务
2. 从任务页开始计时（启动计时器）
3. 在计时进行中，点击"提前结束"（abandoned）
4. 检查任务状态：是否在弃牌堆？是否标记完成？是否触发了反馈弹窗？
5. 查看数据库 `timer_sessions` 表，该记录的 `result` 和 `status` 字段

**预期**：abandoned 任务不应标记为"已完成"，应在弃牌堆或保持可用

### P0-3 抽卡动画状态中断
**验证步骤**：
1. 抽一张卡，卡片开始翻转动画
2. 动画进行中（未完成），立即点击导航切换到其他页面
3. 切回抽卡页面
4. 检查：是否有残留的 `.task-card.drawn-card` 元素？牌堆动画是否正常？

### P1-2 双计时器状态机
**验证步骤**：
1. 从抽卡页启动一个任务计时（抽卡页计时器开始）
2. 切换到任务页，检查任务页计时器面板是否也显示该计时
3. 在任务页点击"停止计时"
4. 切回抽卡页，检查计时 Dock 是否同步停止

**预期（异常）**：两处计时器显示不同步；一方停止另一方仍在走

### P1-3 XSS 风险
**验证步骤**：
1. 新建任务，名称设为 `<img src=x onerror=alert('XSS')>`
2. 打开任务列表
3. 打开抽卡页面抽这张卡
4. 若弹出 alert 则漏洞存在

## 六、Top 3 最可疑 Bug

1. **🔴 计时器 interval 未清理（`app.js` L393）** —— 每次切换页面都创建新 interval 而不清理旧的，会导致计时速度翻倍，严重影响番茄钟准确性
2. **🔴 计时器提前结束任务状态不一致（`app.js` L477-496）** —— 提前结束的计时任务没有明确的后续处理，可能导致任务状态与计时状态脱节，污染数据库
3. **🔴 计时器暂停依赖本地模拟（`app.js` L456-469）** —— 暂停时改写 `started_at` 模拟，刷新页面后暂停状态完全丢失，违背用户预期

---

## 七、建议先修哪个区域

**建议优先修复"计时器区域"**，理由：
1. Bug 数量最多（8 个），其中 3 个高危
2. 计时器是日常使用最频繁的功能之一，用户每天都会触发
3. 计时器修复后可复用"统一状态机"的设计思路，反哺其他区域的状态管理重构
4. 抽卡和任务管理依赖计时器，修复计时器可一并暴露下游问题

**次优先级**：抽卡区域（与计时器高度耦合）

## 一、项目概览

本项目将 **笔记学习系统** 与 **任务发布（游戏化抽卡）系统** 整合一体，提供统一 Web 界面。  
核心由三个子系统组成，以 Flask 后端为桥梁：

```
┌──────────────────────────────────────────────────────────┐
│                    index.html (前端)                      │
│              http://localhost:5000                       │
└──────────────────────┬───────────────────────────────────┘
                       │ fetch(/api/*)
┌──────────────────────▼───────────────────────────────────┐
│            server/backend_api.py (Flask 后端)             │
│         读取 config/config.json                          │
│         连接 SQLite DB                                    │
│         读取笔记 Markdown 文件                             │
└──────┬───────────────────────────────────────┬───────────┘
       │                                       │
       │ SQLite                                │ 文件系统
┌──────▼──────────────────────┐   ┌───────────▼───────────┐
│     任务发布系统/             │   │    笔记处理系统/        │
│    (PySide6 桌面应用)        │   │  (Obsidian Vault)      │
│                              │   │    + 30 个工具脚本      │
│ data/task_publisher.db       │   │    + AI Agent 提示词   │
│ src/models/database.py       │   │ 笔记/ (121 篇 + 150    │
│ src/services/                │   │   知识点)              │
│ src/ui/                      │   │                        │
└──────────────────────────────┘   └────────────────────────┘
```

## 五、统一配置中心

`config/config.json` 是整个系统的唯一配置来源：

```json
{
    "server": {
        "port": 5000,
        "host": "0.0.0.0",
        "debug": true
    },
    "obsidian": {
        "vault_path": "",
        "notes_directory": "笔记处理系统/笔记"
    },
    "api": {
        "openai_api_key": "",
        "claude_api_key": ""
    },
    "database": {
        "task_db_path": "任务发布系统/data/task_publisher.db"
    }
}
```

- `backend_api.py` 通过 `../config/config.json`（相对于 `server/` 目录）找到此配置
- 所有笔记路径和数据库路径均从此文件派生
- 若配置文件缺失，后端会使用硬编码的默认值

## 七、两大子系统详解

### 7.1 笔记处理系统（Obsidian Vault）

**核心位置**: `笔记处理系统/笔记/`

**数据规模**:
- 121 篇课程笔记（分布在 6 个学科文件夹中）
- ~150 个知识点文件（分布在 `笔记/知识点/` 下 6 个学科文件夹中）
- 6 个学科：高等数学、大学物理、线性代数、电子技术、计算机、英语四级

**AI 处理流水线**（离线运行）:

```
原始录音/讲稿
    │
    ▼
[AI: 笔记整理师]  ───  重构为结构化 Markdown（含 [[Wiki 链接]]）
    │
    ▼
[工具: add_wikilinks.py 等]  ───  增强交叉引用
    │
    ▼
[AI: 知识点整理师]  ───  提取知识点到独立 Markdown 文件
    │
    ▼
[AI: 内容审查师 / 结构审查师]  ───  质量审查
    │
    ▼
[工具: check_links.py]  ───  验证链接完整性
```

**30 个工具脚本分类**:

| 类别 | 脚本 | 作用 |
|------|------|------|
| 链接添加 | `add_wikilinks.py`, `add_knowledge_links.py`, `add_high_freq_missing.py` | 为笔记添加 `[[Wiki 链接]]` |
| 链接检查 | `check_links.py`, `check_links_v2.py`, `check_broken_links.py`, `check_missing_links.py`, `check_missing_knowledge.py` | 验证交叉引用完整性 |

### 7.2 任务发布系统（PySide6 桌面应用）

**核心位置**: `任务发布系统/`

**架构**: 分层 MVC

```
main.py (QApplication 入口)
  └── MainWindow (主窗口)
       ├── Database        —— SQLite 17 张表
       ├── TaskService     —— 加权随机算法 + 链式解锁
       ├── GachaService    —— 抽卡（3 卡池）
       ├── StateService    —— 精力/心情/状态追踪
       ├── ExportService   —— JSON 导出
       └── AIImportProcessor —— AI 导入
```

**核心功能**:
- **抽卡系统**: 3 个卡池（碎片 0-15min, 番茄 15-45min, 深度 45min+），基于加权随机抽选任务
- **加权随机**: 权重 = 优先级 × 截止日期紧迫度 × 精力匹配 × 阻力 × 成功率 × 拒绝惩罚 × 策略权重 × 冷却
- **链式解锁**: DFS 递归解锁，自动循环检测，任务完成时触发
- **弃牌堆**: 独立牌堆，支持恢复，自动日/周重置
- **AI 反馈环**: 导出系统状态 JSON → AI 分析 → 导入调整（参数/任务/日程）

**数据库**: SQLite 单文件 `任务发布系统/data/task_publisher.db`，17 张表（tasks, tags, gacha_records, daily_user_state 等）

## 八、两个系统的连接方式

当前两个系统 **仅在 `backend_api.py` 处交汇**，以下是精确的连接点：

### 连接点 1: 共享数据库

```
Web 后端 (backend_api.py)
  └── config.json → "任务发布系统/data/task_publisher.db"
                          ↕ 同一个物理文件
桌面应用 (database.py)
  └── __file__ relative → "任务发布系统/data/task_publisher.db"
```

两者连接到完全相同的 SQLite 文件。这意味着通过 Web 界面操作的任务数据，桌面应用可以直接读写（反之亦然）。

### 连接点 2: 共享前端

`index.html` 同时调用两类 API：
- 任务类：`/api/tasks`, `/api/gacha/draw`, `/api/discard-pile`
- 笔记类：`/api/knowledge/notes`, `/api/knowledge/categories`, `/api/knowledge/points`

用户可在同一 Web 界面中管理任务和浏览笔记。

### 连接点 3: 配置文件

`config.json` 同时定义 `notes_directory` 和 `task_db_path`，被 `backend_api.py` 统一加载。

### 未连接的方面

- 笔记工具脚本 **不引用** 任务系统
- 桌面应用源码 **不引用** 笔记系统
- 两个子系统的目录结构完全独立

### 9.2 backend_api.py 的路径解析逻辑

```python
# config.json 路径：从 server/ 目录向上一级，再进 config/
config_path = os.path.join(os.path.dirname(os.path.dirname(__file__)), 'config', 'config.json')

# 笔记路径：从 config.json 读取 → "笔记处理系统/笔记"
NOTES_DIR = CONFIG['obsidian']['notes_directory']

# 数据库路径：从 config.json 读取 → "任务发布系统/data/task_publisher.db"
DB_PATH = CONFIG['database']['task_db_path']

# 学科路径：硬编码拼接
os.path.join(NOTES_DIR, '知识点', '高等数学')
os.path.join(NOTES_DIR, '知识点', '大学物理')
# ...
```

### 9.3 database.py 的路径解析逻辑

```python
# 从 src/models/database.py 向上三级到 任务发布系统/，再进 data/
DATA_DIR = Path(__file__).parent.parent.parent / "data"
DB_PATH = DATA_DIR / "task_publisher.db"
```

### 9.4 运行时依赖

- **启动学习工具.bat** 必须从项目根目录执行（脚本开头 `cd /d "%~dp0"`）
- **启动任务发布器.bat** 必须从 `任务发布系统/` 目录执行
- Web 后端启动时，`os.getcwd()` 必须为项目根目录
